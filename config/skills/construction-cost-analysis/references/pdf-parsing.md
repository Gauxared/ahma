# Парсинг PDF локальных смет (ЛСР)

Локальные сметные расчёты — самый сложный для парсинга документ в строительном проекте. PDF создаётся из специализированных сметных программ («Гранд-Смета», «РИК», «АВС-4») и имеет колоночную структуру с переменным количеством колонок в разных строках.

## Какие документы парсим

Типичные имена файлов:
- `ТОМ_9_2_1_СМ.pdf`, `ТОМ_9_2_2__СМ.pdf` — локальные сметы, разделены по томам
- `ТОМ_9_3_СМ_ВР.pdf` — сводная ведомость объёмов работ
- `03_Приложение_2-0_Обоснование_НМЦК.rtf` (или PDF) — обоснование НМЦК

Обрати внимание: в одном PDF обычно несколько ЛСР, разделённых разрывом страницы и шапкой нового документа.

## Шаг 1. Конвертация PDF в текст с сохранением колонок

Используй `pdftotext` с флагом `-layout` — он сохраняет колоночную структуру и обеспечивает стабильные позиции данных:

```bash
pdftotext -layout ТОМ_9_2_1_СМ.pdf lsr1.txt
pdftotext -layout ТОМ_9_2_2__СМ.pdf lsr2.txt
```

Получаемый текстовый файл — это исходник для парсинга. Каждая строка — это либо данные позиции, либо строка-заголовок, либо мусор. Различаем по характерным паттернам.

## Шаг 2. Извлечение метаданных ЛСР

В начале каждой ЛСР есть шапка с реквизитами. Ищи паттерны:

```
Локальный сметный расчёт № 02-05
Дорожная одежда
Основание: проект 78/23-ПИР/Р
...
Составлен(а) в текущем (базисном) уровне цен, руб. 4 квартал 2023 г (01.01.2000)
```

Извлекай:
- **Номер ЛСР** (например, `02-05`)
- **Наименование** (например, `Дорожная одежда`)
- **Базис цен** (например, `01.01.2000`)
- **Текущий уровень** (например, `4 квартал 2023`)
- **Итоговую сумму** ("ВСЕГО по смете" в конце ЛСР) — нужна для контроля сходимости

Regex:
```python
import re

# Шапка ЛСР
m = re.search(r'Локальный сметный расчёт №\s*([\d-]+)', text)
lsr_num = m.group(1) if m else None

m = re.search(r'4 квартал (\d{4}) г.*?\((\d{2}\.\d{2}\.\d{4})\)', text)
current_quarter = m.group(1) if m else None
base_date = m.group(2) if m else None

# Итог ЛСР
m = re.search(r'ВСЕГО по смете\s+[\d.\s]+\s+([\d\s,]+\.\d{2})', text)
lsr_total = float(m.group(1).replace(' ', '').replace(',', '.')) if m else None
```

## Шаг 3. Извлечение позиций ЛСР

Каждая ЛСР содержит **позиции** трёх типов:

| Тип | Маркер | Что это |
|---|---|---|
| **Работа** | `ФЕР`, `ФЕРр`, `ТЕР`, `ГЭСН`, `ТСН` | Основная расценка работы |
| **Материал** | `ФССЦ` | Материал по справочнику цен |
| **Перевозка** | `ФССЦпг` | Транспортировка груза |

Каждая позиция имеет:
- Порядковый номер (1, 2, ... или подномер 1.1, 1.1.1)
- Код (например, `01-01-013-04`)
- Наименование
- Единица измерения
- Количество (объём)
- Базисная цена за единицу (в ценах 2001 г.)
- Индекс перевода (например, 11.2)
- Текущая стоимость (после индекса)

Также есть промежуточные строки:
- `Итого по позиции X` — суммирует расценку + подпозиции
- `ВСЕГО по разделу` — итог группы позиций
- `ВСЕГО по смете` — финальный итог ЛСР

## Шаг 4. Структура парсера

Парсер строится как **построчный конечный автомат**:

```python
import re

# Регулярки для типов строк
RE_POSITION_HEAD = re.compile(r'^\s*(\d+(?:\.\d+)*)\s+(ФЕР|ФЕРр|ТЕР|ГЭСН|ТСН|ФССЦ|ФССЦпг)\s+([\d-]+)')
RE_TOTAL_POS = re.compile(r'Итого по позиции\s+(\d+(?:\.\d+)*)')
RE_TOTAL_SMETA = re.compile(r'ВСЕГО по смете')
RE_HEADER = re.compile(r'Локальный сметный расчёт №\s*([\d-]+)')
RE_NUMBERS = re.compile(r'[\d\s]+[,.]?\d*')  # числа с пробелами как разделителями

def parse_lsr_text(text):
    positions = []
    current_lsr = None
    current_position = None
    
    for line in text.split('\n'):
        # Новый ЛСР
        m = RE_HEADER.match(line)
        if m:
            current_lsr = {'num': m.group(1), 'positions': []}
            continue
        
        # Заголовок позиции
        m = RE_POSITION_HEAD.match(line)
        if m:
            pos_num = m.group(1)
            code_type = m.group(2)
            code_num = m.group(3)
            
            # Тип определяется по code_type
            ptype = 'work' if code_type in ('ФЕР', 'ФЕРр', 'ТЕР', 'ГЭСН', 'ТСН') else \
                    'material' if code_type == 'ФССЦ' else \
                    'transport' if code_type == 'ФССЦпг' else 'unknown'
            
            current_position = {
                'lsr_num': current_lsr['num'] if current_lsr else None,
                'pos_num': pos_num,
                'code_type': code_type,
                'code_num': code_num,
                'type': ptype,
                'name_lines': [],
                'numbers': [],
            }
            positions.append(current_position)
            continue
        
        # Продолжение позиции — текст наименования или числа
        if current_position:
            # Извлечь числа из строки
            nums = re.findall(r'-?[\d\s]+[,.]?\d*', line)
            for n in nums:
                n_clean = n.replace(' ', '').replace(',', '.')
                try:
                    current_position['numbers'].append(float(n_clean))
                except:
                    pass
            
            # Текст до первого числа — продолжение наименования
            text_part = re.match(r'^([^\d-]+)', line)
            if text_part and text_part.group(1).strip():
                current_position['name_lines'].append(text_part.group(1).strip())
    
    return positions
```

Это упрощённая версия — реальный парсер требует тонкой настройки под формат конкретной сметной программы. См. готовый код в `scripts/parse_lsr_pdf.py`.

## Шаг 5. Постобработка

После извлечения сырых данных:

1. **Склей наименования** позиций (часто разбиты на 2-3 строки)
2. **Идентифицируй колонки чисел** — обычно в строке позиции это:
   - № строки, объём, базисная стоимость на единицу, индекс, текущая стоимость на единицу, итого по позиции базис, итого по позиции текущая
3. **Удали мусор** — заголовки страниц, нумерацию страниц, фразы типа "Продолжение таблицы"
4. **Проверь сходимость:** сумма всех "ВСЕГО по смете" должна сойтись с шапками ЛСР

## Шаг 6. Контроль качества — это критично

**Сходимость = 100% или ничего**. После парсинга:

```python
# Сумма из шапок ЛСР (извлечена из метаданных)
total_from_headers = sum(lsr['total'] for lsr in lsr_meta)

# Сумма из позиций (только "ВСЕГО по смете")
total_from_positions = sum(p['cost_current'] for p in positions if p['is_total_smeta'])

diff = abs(total_from_headers - total_from_positions)
assert diff < 1.0, f"Расхождение {diff:.2f} руб — парсер сломан!"
```

В реальных проектах допустимо расхождение до 1 рубля (округление до тыс. руб в шапках). Если больше — ищи ошибку.

## Типичные грабли

1. **Длинные наименования** разбиваются на много строк — нужен буфер для склейки
2. **Числа с пробелами как разделителями тысяч** (`1 234 567,89`) — обработай аккуратно
3. **Минус в начале числа** — для вычитаний материалов в составе расценки (`-0,3` единицы материала)
4. **Подпозиции ФССЦ** имеют свой код (например `5-1`, `5-2`), и их итоги суммируются в "Итого по позиции 5"
5. **Несколько ЛСР в одном PDF** — следи за разрывами и шапками
6. **Кодировки шрифтов** — иногда `pdftotext` выдаёт мусор для нестандартных шрифтов. Решение: `pdftotext -layout -enc UTF-8`

## Чек-лист после парсинга

Перед переходом к этапу 4 (сборка Excel) проверь:

- [ ] Все ЛСР извлечены (количество совпадает с титульным листом тома)
- [ ] Сумма "ВСЕГО по смете" каждой ЛСР сходится с шапкой
- [ ] Общая сумма всех ЛСР сходится с итогом по тому
- [ ] У каждой позиции есть тип (work / material / transport)
- [ ] У каждой работы есть код ФЕР (нужен для группировки на этапе 6)
- [ ] У каждого материала есть единица измерения и количество
