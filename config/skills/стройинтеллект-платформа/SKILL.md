# Роль экипажа в рабочей папке платформы

Ты работаешь не в чате, а в рабочей папке прогона. Читай файлы командами
оболочки (`cat`, `grep`, `awk`, `python3`, `view_image` для картинок); ничего в
исходниках не меняй. Единственное, что ты создаёшь, — свой итог `выход/<Имя>.json`
(и при желании — рабочие файлы в `выход/черновики/<Имя>/`).

## Устройство папки

| путь | что там |
|---|---|
| `ОБЪЕКТ.md` | перечень документов партии: файл · вид · разбор · позиций · итог · сошлось · где читать; итог сводного расчёта |
| `сметы/<файл>.tsv` | позиции разобранных смет: № · раздел · наименование · шифр · ед. · кол-во · сумма · **строка листа** — её называй в находках |
| `сметы/<файл>.сходимость.md` | что насчитал расчётный модуль (числа считает код, не ты) |
| `документация/*.txt` | текст РД, договоров, ТЗ, писем и книг, не являющихся сметами (смета контракта, ведомость, график, счета) — построчно |
| `листы/*.png|jpg` | листы чертежей и фотографии — смотри `view_image` |
| `нормативы.tsv` | наименование каждого шифра из смет по каталогу |
| `опора/<Роль>.md` | ТВОЯ опорная база — тот xlsx, о котором говорит твой промпт, переложен текстом; режим [БЕЗ БАЗЫ] не действует, если файл есть |
| `ядро.md` | общие правила экипажа (Ядро_СИ, реконструкция) |
| `передачи/для-<Имя>.md` | блоки, адресованные тебе |
| `выход/<Имя>.json` | итоги ролей, уже отработавших; свой пиши сюда же |
| `инструменты/финмодель` · `поиск` · `страница` | команды платформы: финмодель считает код, поиск и страницы читает код (см. ниже) |
| папка партии | исходные файлы объекта, только чтение |

## Итог роли — `выход/<Имя>.json`

Один объект JSON, все поля обязательны (пусто — `""`, `0`, `[]`):

```json
{
  "verdict": "🟡 … одной фразой",
  "summary": ["ЗАКЛЮЧЕНИЕ — 4 строки, каждая с рублёвым эффектом"],
  "findings": [{
    "severity": "critical|high|medium|low|info",
    "statement": "что не так",
    "basis": "почему, с тегом [ИСТОЧНИК: документ, дата, статус]",
    "document": "имя файла из ОБЪЕКТ.md или \"\"",
    "row": 0,
    "impactRub": "десятичная строка рублей или \"\"",
    "sourceStatus": "факт|предположение|неизвестное"
  }],
  "sections": [{ "id": "convergence", "title": "…", "purpose": "…", "columns": ["…"], "rows": [["…"]] }],
  "openQuestions": [{ "question": "…", "owner": "от кого нужны данные", "dueBy": "к какому сроку" }],
  "handoffs": [{ "to": "Ваныч", "subject": "предмет с цифрой и обоснованием", "disputed": "спорная зона ⚠/❌", "needed": "что сделать и к какому сроку" }],
  "assumptions": [{ "assumption": "…", "verification": "чем и когда подтверждается" }],
  "alerts": [{ "situation": "…", "moneyEffect": "…", "document": "…", "decision": "какое решение нужно Артемию" }],
  "nextTakt": "СЛЕДУЮЩИЙ ТАКТ одной строкой"
}
```

`row` — «строка листа» из TSV сметы: по ней платформа вешает на находку ссылку
на исходную книгу и подставляет сумму строки. Сумму без строки не выдумывай —
пиши в `impactRub`, она попадёт в основание словом «по оценке роли».

## Обязательные листы каркаса (id листа должен совпадать)

- Людмила: `convergence` «Сходимость сметы» · `price_basis` «Ценовая база и пересчёт» · `overheads` «НР и СП» · `market_check`
- Денчик: `norm_profile` «Нормативный профиль» · `composition_check` «Сверка состава документации»
- Ваныч: листы финмодели по промпту (ценообразование, актирование, БДДС) · `market_check`
- Марина: карта лид-таймов, КП, влияние на маржу · `market_check`
- Артемий: `object_summary` «Сводка по объекту» (Смежник · Вердикт · Главное замечание · Влияние) · `start_conditions` «Условия старта» (Условие · Кто закрывает · Срок · Что будет, если не закрыть)
- Тимофей: `scenarios` · `works` · `delay_risks` · `assumptions`
- остальные — листы своего документа пакета по промпту; плюс у всех — `handoffs` «Передачи смежникам» заполняется платформой из `handoffs`.

Лист про предмет, которого на объекте нет, не заводи — пустая таблица с чужим
названием хуже отсутствующей.

## Рыночная проверка цен — лист `market_check`

В сеть ходи ТОЛЬКО инструментами платформы. Замерено: DuckDuckGo, Google и
Яндекс с адреса сервера отдают CAPTCHA, Bing отдаёт боту подставную выдачу
(Toyota и Gmail на запрос о битуме) — `curl` по поисковикам и `grep` по HTML
приносят мусор, а домены «из памяти» источниками не являются.

```bash
инструменты/цены битум БНД 70/100 --регион Дагестан     # Avito региона + tradedir.ru: цена, продавец, город, ✅ в регионе/⚠ вне; прайсы поставщиков региона
инструменты/источник список                             # парсеры авторитетных площадок (браузер): имена и что дают
инструменты/источник pulscen битум БНД 70/100 --регион Дагестан   # карточки Пульса цен: цена «от», поставщик, город, ✅/⚠ регион
инструменты/поиск битум БНД 70/100 цена тонна          # до 10 ссылок: заголовок, url, описание, канал выдачи
инструменты/страница https://mahachkala.scheben-rf.ru/price/   # текст без разметки + СТРОКИ С ЦЕНАМИ
```

Порядок: сначала `цены` по каждому ключевому ресурсу с регионом объекта (регион
— из НМЦК, контракта, адреса объекта); потом `поиск` для того, чего `цены` не
дали; каждую ссылку, которую ставишь в лист, ОТКРОЙ `страница` — url без
открытой страницы в лист не идёт (прогон 13: «цена не извлечена» у трёх строк,
хотя прайс Щебень-РФ открывался и содержал 40 строк цен). Предложения «⚠ вне
региона» — ориентир без доставки, только со статусом ⚠.

Инструмент сам пробует каналы (DuckDuckGo через прокси, API по ключу, Bing) и
отбрасывает CAPTCHA и выдачу не о запросе; первая строка ответа называет канал
и причины отказов. «Все каналы отказали» — тоже ответ: в строке листа пиши
«источник недоступен: <заметка инструмента>», а рыночную цену бери из навыка
`construction-cost-analysis` (`references/market-prices-russia.md`: диапазоны по
регионам 2026) со статусом «⚠ бенчмарк навыка», не «неизвестно»: диапазон с
источником лучше пустой клетки. Поставщики, заводы и ФГИС ЦС предпочтительнее
агрегаторов.

Колонки листа: Позиция/ресурс · Цена в документах, ₽ · Рыночная цена, ₽ ·
Источник (url, который вернул инструмент, или «навык construction-cost-analysis») ·
Дата источника · Отклонение, % · Статус ✅/⚠. Не меньше пяти ключевых ресурсов
объекта по деньгам. Каждая цифра из сети — `[ИСТОЧНИК: <url>, <дата>, ✅/⚠]`.
Сетевой части — не больше половины хода.

## Финмодель — только `инструменты/финмодель`

Сценарии, маржу, БДДС и стоимость денег считает код по формуле
`calculation.finance-model` (реестр формул платформы), не роль: без инструмента
прогоны на одних документах давали разброс от −50,8 до +74,5 млн ₽.

```bash
инструменты/финмодель --цена 1181000000 --ндс 0.22 --срок 18 \
  --статья 'Материалы=520000000' --статья 'Работы и механизмы=310000000' --статья 'Накладные=60000000' \
  --аванс 0.3 --отсрочка 1 --обеспечение 0.1 --бг 0.03 --ставка 0.18 --красная 0.05 \
  --год 2026=0.05 --год 2027=0.55 --год 2028=0.40 [--json]
```

Вывод: параметры, выручка без НДС, статьи с долями, три сценария (база /
оптимист −5 % / стресс +15 %) с валовой маржой, БГ, стоимостью денег, прибылью,
маржой и кассовым разрывом (первый месяц, пик), недостача до красной линии,
допущения расчёта. Переноси в листы финмодели как есть с тегом
`[ИСТОЧНИК: инструменты/финмодель calculation.finance-model v1, <дата>, ✅]`;
у каждого ПАРАМЕТРА — свой источник (документ, строка, дата). Своё суждение
прикладывай к параметрам, не к итогу; при сомнении в параметре прогони дважды
и покажи оба результата.

## Результат обязателен

Четыре запрета Ядра р.4 действуют. «Заблокировано до дозагрузки» как итог — это
запрет №2. Считай на том, что есть, помечай ⚠ и называй точность в процентах;
дозагрузка — открытыми вопросами с адресатом и сроком. Книги «книга-не-смета»
(смета контракта, ведомость объёмов, обоснование НМЦК, график) — источники цены
и объёмов наравне с ЛСР.
