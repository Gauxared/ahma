# СтройИнтеллект: договорные требования и приёмка

## 1. Назначение

Документ переводит разделы 1–15 исходного ТЗ в проверяемые требования. Перефразирование не меняет договорный смысл; при споре используется literal text DOCX.

Формат ID:

```text
REQ-TZ-<section>-<number>
ACC-TZ-<section>-<number>
DEP-TZ-15-<number>
```

Каждый active requirement materializes как запись:

```yaml
requirement_id: REQ-TZ-5-11
class: contract
source_id: SRC-TZ-1.0
source_location: "§5.3, строка режима Экспресс"
literal_text: "Вывод, ключевая цифра, рекомендация. До 15 строк, без таблиц"
literal_hash: sha256
decision: include
acceptance_refs:
  - TEST-MODE-EXPRESS-FORMAT
  - TEST-MODE-EXPRESS-SLA
```

`literal_hash` и точный paragraph/table-cell anchor формируются детерминированным DOCX extraction pass. Отсутствие этих полей блокирует переход requirement в status `verified`.

## 9. Архитектура и расчёты

`REQ-TZ-6-01`: система размещается на инфраструктуре Исполнителя в РФ.

`REQ-TZ-6-02`: числа в ответах и выгрузках вычисляет расчётный модуль, а LLM интерпретирует и формулирует.

Десять обязательных расчётов:

1. `CALC-TZ-01` — сходимость разделов и итога;
2. `CALC-TZ-02` — позиция сметы `quantity × unit_price`;
3. `CALC-TZ-03` — отклонение подрядчика от опорного значения;
4. `CALC-TZ-04` — себестоимость по элементам и ₽/м²;
5. `CALC-TZ-05` — проценты и график выборки проектного кредита;
6. `CALC-TZ-06` — помесячный БДДС и первый кассовый разрыв;
7. `CALC-TZ-07` — три сценария маржи;
8. `CALC-TZ-08` — крайний срок заказа;
9. `CALC-TZ-09` — обратный расчёт срока;
10. `CALC-TZ-10` — пеня ₽/день от ключевой ставки.

`REQ-TZ-6-03`: НДС и ключевая ставка являются dated parameters, а не constants в коде.

`REQ-TZ-6-04`: provider и model меняются конфигурацией.

`REQ-TZ-6-05`: prompts хранятся с version control и меняются без изменения domain code.

`REQ-TZ-6-06`: минимум два эталонных объекта определяют формат и глубину ответа, но их числа не переносятся в новый объект.

## 10. Опорная база

`REQ-TZ-7-01`: договорный Excel содержит 13 именованных разделов: работы, материалы, long-lead оборудование, ₽/м², финансирование, труд, выработка, алгоритмы, нормативы, объекты, уроки, plan/fact и подрядчики.

`REQ-TZ-7-02`: каждая числовая запись имеет:

- value;
- unit;
- year или effective period;
- source;
- status `fact | estimate | no_data`;
- checked_at.

Import status mapping:

| APRI import status | Canonical status | Numeric value |
|---|---|---|
| `fact` | `source_confirmed` | Required |
| `estimate` / `ориентир` | `estimate` | Required |
| `no_data` / `нет данных` | `unknown` | Forbidden |

`calculated` создаётся только Calculation Engine. Import adapter не может маркировать исходную ячейку как `calculated`.

`REQ-TZ-7-03`: значение старше 90 дней помечается как требующее проверки во всех результатах, где оно использовано.

Тринадцать листов являются import profile АПРИ, а не максимальным доменным schema платформы.

## 15. Приёмка

Контрольный набор: два объекта АПРИ, по каждому есть ручной расчёт специалистов Заказчика.

| ID | Gate | Критерий |
|---|---|---|
| `ACC-TZ-12-01` | Extraction | ≥95% корректно извлечённых позиций |
| `ACC-TZ-12-02` | Convergence | 0 ₽ необъяснённого расхождения |
| `ACC-TZ-12-03` | Violations | ≥70% полноты относительно ручного расчёта |
| `ACC-TZ-12-04` | ₽/м² | В пределах протокольного порога этапа 2 |
| `ACC-TZ-12-05` | Provenance | 0 чисел без маркера статуса |
| `ACC-TZ-12-06` | SLA | В пределах режима |
| `ACC-TZ-12-07` | Competency quality | ≥80% чек-листа по каждой компетенции |

Denominator, matching и чек-лист калибруются после этапа 1 и фиксируются протоколом до приёмки. Минимумы 95%, 70% и 80% не снижаются без письменного change request к ТЗ.

Denominator и matching rules должны быть зафиксированы до запуска контрольного набора:

- что считается позицией;
- как учитывать merged/split rows;
- что является нарушением;
- какие различия считаются эквивалентными;
- какая rounding policy применяется к 0 ₽.

## 18. Release gate

Pilot release не может быть принят, если:

- active `requirement_coverage` меньше 100%;
- requirement не имеет source anchor, literal hash, class, decision или acceptance refs;
- отсутствует evidence хотя бы одного `ACC-TZ-*`;
- обязательный параметр не имеет schema и provenance;
- parser denominator не согласован;
