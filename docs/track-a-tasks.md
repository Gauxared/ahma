# Трек A: корпус и каталог

Порядок работы тот же, что в M1: **спецификация → тесты → реализация →
проверка → коммит**.

Трек идёт в двух зонах (ADR-R-021). Зона A1 — подготовка в контуре 7КЛ: сырые
документы, разбор, обезличивание. Зона A2 — поставка: в инсталляцию уходит
нормализованный набор данных, но не документы третьих лиц.

## Почему это раньше M2

Механика сопоставления готова (T1), но каталог пуст, и `si run parse-estimate`
на курганском комплекте показывает 0 позиций по шифру из 101. От каталога прямо
зависят критерии приёмки §12.1ж (сопоставление предложений) и §12.1з
(обоснованность оценки). Пока его нет, эта часть системы работает вхолостую.

## Измерено до начала (25.08.2026)

Корпус `reference-system-new/Выход/АПРИ`: **479 файлов xlsx, 125 МБ**.
Наивный проход по ним падает, и это не мелочь реализации, а свойство задачи:

1. **Файл 38 МБ** (`3 Исполнительная титула 21-36, генплан1.xlsx`) исчерпывает
   кучу 4 ГБ в одиночку: ExcelJS строит полную объектную модель книги.
2. **Файл 3.3 МБ** (`ОСК_Йошкар-Ола_ЕДИНЫЙ_документ_команды_v4.xlsx`) роняет
   читатель ошибкой `Cannot read properties of undefined (reading 'comments')`.

Значит пакетный разбор корпуса не может быть циклом «прочитать и разобрать».
Ему нужны границы и явный учёт отказов.

## A1. Каталог канонических позиций из корпуса

**Зачем.** Наполнить `CanonicalItemRegistry` шифрами ФЕР/ГЭСН/ФССЦ из реальных
смет, чтобы кодовый путь канонизации (ADR-R-013) заработал на данных.

**Объём.**

1. Обход корпуса с явными правилами отбора и порогом размера файла.
2. Учёт каждого пропуска с причиной: превышен размер, не смета, ошибка чтения.
3. Разрешение конфликтов: один шифр встречается с разными наименованиями и
   единицами — выбор детерминированный и объяснимый.
4. Операция обслуживания `build-catalogue` (`kind: maintenance`, ADR-R-022)
   и команда `si maintain build-catalogue`.
5. Каталог как конфигурационный бандл со схемой и хэшем содержимого.

**Критерии приёмки.**

- Прогон по всему корпусу завершается без падения процесса.
- Ни один файл не пропускается молча: у каждого пропуска есть причина
  в отчёте (инвариант §9).
- Конфликт по шифру разрешается детерминированно: повторный прогон на том же
  корпусе даёт тот же каталог.
- Каталог проходит валидацию схемой при загрузке в композиционном корне.
- Покрытие курганского комплекта измерено и зафиксировано в отчёте. Значение
  не назначается заранее: какая доля из 97 позиций с шифрами найдётся в
  каталоге — это факт о корпусе, а не цель.

---

### Результат A1 (25.08.2026)

Прогон по корпусу завершается без падения, каждый файл учтён:

```
Файлов всего      : 479
  разобрано       : 79
  не смета        : 391
  ошибка чтения   : 7
  превышен размер : 2
                    ─────
                    479
Позиций           : 3087, без шифра 700
Записей каталога  : 474
  шифров без единицы (не в каталоге): 58
Конфликтов        : 87
```

### Покрытие: 7%, а не 96%

Первый замер дал 97 из 101 позиции курганского комплекта — и оказался
**круговым**. Сверка по хэшам содержимого показала, что все пять курганских
файлов лежат и в корпусе тоже: каталог покрывал их потому, что видел ровно
эти файлы.

Честный замер на каталоге, собранном БЕЗ Кургана (421 запись из 76 смет):

| Файл | Позиций | По шифру |
|---|---:|---:|
| Курган СОТВ | 44 | 4 |
| Курган ЭОМ | 54 | 3 |
| ПНР СОТВ | 2 | 0 |
| СП и СИ | 1 | 0 |
| **Итого** | **101** | **7 (7%)** |

Из 97 позиций, у которых есть шифр, каталог нашёл 7.

### Что это значит

Механизм кодовой канонизации работает — при полном каталоге он даёт 100%
по позициям с шифрами. Проблема в **источнике каталога**.

Корпус из 76 смет покрывает новый объект плохо, потому что виды работ не
совпадают: в корпусе фундаменты и промышленный монтаж, в Кургане —
железнодорожная сигнализация и электроснабжение. Накопление корпуса эту
задачу не решает: расценок в ФЕР/ГЭСН/ФССЦ порядка сотни тысяч, и «шифры,
которые мы встретили» никогда не станут справочником.

**Правильный источник — сама сметно-нормативная база**, а не встреченные
сметы. ФЕР, ГЭСН и ФССЦ — публикуемые государственные справочники.

В корпусе их в машинном виде нет: `Нормативка/11` содержит только PDF и DOC
приказов Минстроя (методику, а не таблицы расценок), `БД Kodeks6` — установщик
Windows с проприетарной базой, `БД Stroyka` — файл справки.

### Следствия

1. Каталог из ФГИС ЦС либо из выгрузки сметной программы — **входная
   зависимость проекта**, а не задача разработки. Её надо заявить наравне
   с материалами по §15.1.
2. До появления справочника нагрузку несёт текстовый путь канонизации
   (M5, ADR-R-013), и его приоритет выше, чем предполагалось.
3. Замер покрытия обязан быть вневыборочным. Любая будущая цифра по
   §12.1ж и §12.1з, полученная на корпусе, содержащем контрольный объект,
   недействительна.

## A2. Импорт ФСНБ-2022 из открытых данных

**Результат (25.08.2026).** Каталог построен из государственной базы:
**56 192 нормы**, все с единицами измерения, без повторов шифра.

### Как получен источник

Раздел ФРСН портала ФГИС ЦС отдаёт файлы только после капчи — это сознательный
сигнал владельца против автоматизации, и обходить его нельзя.

Но у ФГИС ЦС есть официальный **набор открытых данных**: `GET /api/opendata`
возвращает 15 наборов, среди них «ФСНБ-2022» (владелец ФАУ «Главгосэкспертиза
России»). Метаданные набора содержат путь файла, который отдаётся через
`/api/values/GetFileContent/{path}` без капчи. Открытые данные для того и
публикуются, чтобы их читали машины; путь не входит в запрещённый robots.txt
раздел `/data-storage/`.

Состав архива — 165 МБ XML со схемами XSD:

| Файл | Норм |
|---|---:|
| ГЭСН.xml | 29 976 |
| ГЭСНм.xml | 19 208 |
| ГЭСНр.xml | 3 978 |
| ГЭСНп.xml | 2 605 |
| ГЭСНмр.xml | 425 |
| ФСБЦ_Мат&Оборуд.xml | 45 437 |
| ФСБЦ_Маш.xml | 1 732 |

Итого **103 361 запись**: нормы ГЭСН и сметные цены ресурсов ФСБЦ.

### Покрытие Кургана: 98 из 101

| Файл | Позиций | По шифру |
|---|---:|---:|
| Курган СОТВ | 44 | 42 |
| Курган ЭОМ | 54 | 54 |
| ПНР СОТВ | 2 | 2 |
| СП и СИ | 1 | 0 |
| **Итого** | **101** | **98 (97%)** |

Замер честен по построению: каталог собран из государственной базы, курганский
комплект в неё попасть не мог.

Оставшиеся три позиции имеют обоснование вида `ТЦ_<ИНН>_<дата>_<пункт>` —
текущая цена по коммерческому предложению (конъюнктурный анализ). Это два
криптошлюза ViPNet и специальные работы в отношении технических средств.
Нормативного шифра у них нет по существу, и пополнение каталога их не найдёт:
законен только текстовый путь.

### Уточнение прежнего вывода

Пока каталог содержал только нормы ГЭСН, счёт был 97 из 101, и в отчёте
значилось «4 позиции без шифра». Это оказалось неточным: одна из четырёх имела
шифр `ФСБЦ-08.3.05.02-0021`, который мы не умели читать. Она была не позицией
без шифра, а позицией с шифром неподдержанной системы — разница существенная,
потому что первое означает предел метода, а второе — пробел реализации.

### Две ловушки формата ФСБЦ

**Тег `<Resource>` значит разное в двух файлах одного архива.** В ГЭСН это
расход внутри нормы (`EndName` + `Quantity`), и его надо игнорировать. В ФСБЦ
это сама запись каталога (`Name` + `Prices`), и игнорировать надо уже `<Work>`.
Различаются по наличию `Name`.

**Разделитель между системой и кодом.** ГЭСН пишет шифр слитно
(`ГЭСНм08-03-572-06`), ФСБЦ — через дефис (`ФСБЦ-08.3.05.02-0021`). Оставленный
в коде дефис не совпал бы ни с одной записью каталога.

Имя системы взято не из XSD, а из реальной сметы: в курганском ЭОМ шифр записан
именно как `ФСБЦ-…`, хотя схема называется `FSBC_FSSC_FSEM` и подсказывала бы
ФССЦ или ФСЭМ.

### Дефект, найденный этим замером

Первый прогон дал 24%, причём по СОТВ — ноль из 44. Причина оказалась не в
данных, а в разборе: «ГЭСНм08-03-572-06» начинается и с «ГЭСН», и с «ГЭСНм»,
и при проверке короткого префикса первым шифр разбирался как ГЭСН с кодом
«м08-03-572-06». Такого кода нет ни в одном справочнике, и все монтажные
позиции молча не находились.

У ГЭСН, ФЕР и ТЕР есть отраслевые ветви — монтаж, ремонт, пусконаладка,
монтаж при ремонте. Это разные справочники, а не варианты записи. Порядок
префиксов от длинного к короткому закреплён регрессионным тестом.
