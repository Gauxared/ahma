Вывод: Kodeks6 не стоит переносить. Актуальные тексты тех же документов уже лежат в `Нормативка/` в PDF.

## 3. Опорные базы ролей

### 3.1 Как наша система читает опорную базу

- Путь задаётся в `config/agents/<id>/manifest.json` полем `referenceBase` (относительный путь от корня репозитория, напр. `reference-system/Опорная_база_Людмила_Сметчик_v1.0.xlsx`). Схема — `platform/config/agent-roster.ts:108` (`referenceBase: z.string().min(1).optional()`; «отсутствует — агент работает в режиме [БЕЗ БАЗЫ]»).
- Чтение — `platform/config/reference-base-loader.ts::loadReferenceBase` → `platform/storage/xlsx-reader.ts::readXlsxSheet` по индексу листа (0…40), лист с именем `/навигатор/i` пропускается; каждый лист → `parseReferenceSheet` (`@modules/agents/reference-base.js`), затем `renderReferenceBase(base, 100_000)` в текст.
- Потребители: `platform/bootstrap.ts:557` (`referenceBaseFor(capability)` для 9 агентов, кэш по пути, `configHashes` для провенанса); `platform/codex/crew-reviewers.ts:180–185` (для прогона Codex: текст базы кладётся в `опора/<Имя>.md` рабочей папки, `platform/codex/workspace.ts:212–216`); промпт роли говорит об этом в `platform/codex/crew.ts:361–364`; навык `config/skills/стройинтеллект-платформа/SKILL.md:23`.
- Знание, которое база «предоставляет», объявлено в `config/knowledge-sources.json` (extension `reference-base`: work_rates, materials, labour_rates, normative_status, …).
- **`config/crew/bases/` в коде не встречается** (grep по `platform/`, `config/`, `docs/` на `crew/bases` и `bases/` — 0 совпадений в коде; папка добавлена коммитом fc5169d вместе с нативной оркестрацией, но не подключена).
