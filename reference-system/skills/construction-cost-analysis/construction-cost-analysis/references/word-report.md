# Аналитическая справка в Word

Финальный артефакт — Word-документ с аналитической справкой по проекту. Это документ, который пользователь может показать руководству, заказчику или партнёрам.

## Когда делать

Делай **только когда пользователь явно попросит**: "сделай аналитическую справку", "сформируй отчёт", "оформи в Word", "сделай документ для руководства".

Не делай автоматически после Excel — отчёт занимает время, не всегда нужен.

## Что подготовить заранее

Прежде чем создавать справку, **обязательно прочти**:
1. `/mnt/skills/public/docx/SKILL.md` — общие правила работы с .docx
2. У тебя должен быть готовый Excel-файл с финансовым результатом (этапы 1-6 выполнены)

## Структура справки (8 разделов + титул)

```
ТИТУЛ
  - Название "АНАЛИТИЧЕСКАЯ СПРАВКА"
  - Подзаголовок (тип объекта)
  - Полное наименование объекта (с границами участка)
  - Реквизиты: заказчик, регион, шифр проекта, проектировщик
  - Документ-приложение (имя Excel-файла)
  - Дата подготовки

──────────────────────────────────────────

1. КРАТКОЕ РЕЗЮМЕ (1 страница)
  - Главный вывод одним предложением ("Объект прибыльный" / "Объект убыточный")
  - Сводная таблица ключевых цифр (НМЦК, прибыль, маржинальность)
  - 1-2 абзаца про главный риск и главный заработок

2. О ПРОЕКТЕ (1-2 страницы)
  - Основные параметры (тип, регион, протяжённость, НМЦК)
  - Структура работ (таблица с ЛСР и их стоимостью)
  - Уровни цен (базис / текущий / целевой)

3. КАК ЧИТАТЬ ФАЙЛ smeta_aksonomia.xlsx (1-2 страницы)
  - Карта файла (таблица из 11 листов)
  - Логика чтения в 5 шагов
  - Цветовая кодировка

4. ФИНАНСОВЫЙ РЕЗУЛЬТАТ: НА ЧЁМ ЗАРАБОТОК, НА ЧЁМ УБЫТОК (2-3 страницы)
  4.1. По материалам (таблица с топ-убытками и топ-заработками)
  4.2. По работам (таблица с группами кодов ФЕР, коэф., дельтой)

5. ИСТОЧНИКИ ДАННЫХ (1-2 страницы)
  5.1. Сметная стоимость — из исходных документов (список приложений)
  5.2. Рыночные цены материалов — поставщики Дагестана / региона
  5.3. Коэффициенты рыночности работ — отраслевые ориентиры

6. МЕТОДОЛОГИЯ РАСЧЁТА (1 страница)
  6.1. Индексирование цен (таблица: базис → текущий → целевой)
  6.2. Логика дельты (формула в рамке)
  6.3. Разграничение материалов и работ (без двойного счёта)

7. ПОГРЕШНОСТИ И ОГРАНИЧЕНИЯ (1-2 страницы)
  7.1. Погрешность извлечения данных (обычно <0,01%)
  7.2. Погрешность рыночных цен (±10-15%)
  7.3. Погрешность коэф. рыночности (±5-7%)
  7.4. Что НЕ учтено (НДС, НР+СП в смете, кассовые разрывы, кредиты)
  7.5. Итоговая погрешность (диапазон прибыли ±15%)

8. ВЫВОДЫ И РЕКОМЕНДАЦИИ (1 страница)
  8.1. Главные выводы (5 пунктов)
  8.2. Что делать дальше (5 конкретных шагов)
  - Подпись внизу
```

**Итого: 12-15 страниц** для среднего проекта.

## Технические требования

### Шрифт и размер

```javascript
const FONT = "Arial";  // универсально доступен
// Размеры в half-points (size: 22 = 11pt)
// - Основной текст: 22 (11pt)
// - Заголовки H1: 32 (16pt)
// - Заголовки H2: 26 (13pt)
// - Заголовки H3: 22 (11pt), bold
// - Текст в таблицах: 20 (10pt)
// - Подписи и сноски: 18 (9pt)
```

### Цвета (согласованы с Excel)

```javascript
const C_DARK = "1F4E78";       // тёмно-синий — заголовки
const C_ACCENT = "C00000";     // тёмно-красный — главные акценты
const C_GREEN = "548235";      // зелёный — заработки
const C_RED = "9C0006";        // красный — убытки
const C_GREY = "595959";       // серый — справочная информация
const C_LIGHT_BLUE = "D9E1F2"; // светло-голубой — заголовки таблиц
const C_LIGHT_GREEN = "C6EFCE"; // светло-зелёный — заработки в таблицах
const C_LIGHT_RED = "FFC7CE";   // светло-красный — убытки в таблицах
const C_LIGHT_YELLOW = "FFE699"; // жёлтый — итоговые суммы
```

### Колонтитулы

В **header** (правый край): название проекта курсивом с нижней чертой.
В **footer** (центр): "Стр. X / Y".

### Размер страницы

US Letter (12240×15840 DXA) с полями по 1 дюйм (1440 DXA). Не A4 — она по умолчанию в docx-js, но US Letter более стандартен для бизнес-документов в РФ.

## Создание через docx-js

Создаётся через Node.js пакет `docx`:

```bash
npm install -g docx  # если не установлен
```

См. готовый код в `scripts/build_word_report.js`.

### Ключевые правила (из общего SKILL.md по docx)

1. **Никаких `\n`** в тексте — только отдельные `Paragraph`
2. **Никаких символов `•`** в тексте — только через `numbering` с `LevelFormat.BULLET`
3. **Таблицы — двойная ширина**: `columnWidths` на таблице + `width` на каждой ячейке
4. **`ShadingType.CLEAR`** — не `SOLID` (иначе чёрный фон)
5. **`PageBreak`** — внутри `Paragraph`, не отдельно
6. **Размеры в DXA**: 1440 DXA = 1 дюйм

### Валидация

После создания:
```bash
python3 /mnt/skills/public/docx/scripts/office/validate.py output.docx
```

Если валидация фейлится — открой XML, поищи проблему. Чаще всего:
- Незакрытые теги
- Неправильный порядок элементов в `<w:pPr>`
- Отсутствие `xml:space="preserve"` в `<w:t>` с пробелами

## Шаблонные формулировки

### Главный вывод (резюме)

**Если объект прибыльный:**
> "Объект — прибыльный для подрядчика. По итогам сопоставления сметной стоимости с актуальными рыночными ценами материалов и работ в [регион] на [квартал] расчётная дополнительная прибыль подрядчика составляет ≈ [сумма] млн руб сверх прибыли, заложенной в сметные нормативы НР+СП и резерва на непредвиденные расходы."

**Если объект убыточный:**
> "Объект убыточен для подрядчика. По итогам сопоставления сметной стоимости с актуальными рыночными ценами материалов и работ в [регион] на [квартал] расчётная потеря составляет ≈ [сумма] млн руб. Это означает, что после оптимизации сметных НР+СП объект может оказаться на грани окупаемости или с отрицательной маржой."

### Про битум (типичная позиция убытка)

> "Главный финансовый риск — битум БНД 70/100. Реальная рыночная цена битума (~55 000 руб/т) почти в [N] раза выше сметной (~21 300 руб/т). По этой позиции подрядчик потеряет ≈ [сумма] млн руб. Это типичная проблема индексного метода — индексы Минстроя на нефтепродукты хронически отстают от рынка."

### Про дорожную одежду (типичная позиция заработка)

> "Основной источник заработка — устройство дорожной одежды и земляные работы (главы 2-05, 2-01, 2-02). На этих статьях заработок составляет ≈ [сумма] млн руб, что объясняется типичной маржей подрядчика на работах с собственной техникой (8-18%)."

### Финальное предупреждение

> "Совокупная погрешность расчёта прибыли — ±15% от расчётной величины. То есть реальная дополнительная прибыль на проекте находится в диапазоне [нижняя] — [верхняя] млн руб (при условии, что [главный риск] удастся [минимизировать]). С учётом сметной маржи и резерва общая ожидаемая прибыль подрядчика на проекте — 25-35 млн руб (6-8% от НМЦК), что соответствует типичной маржинальности государственных дорожных контрактов в РФ."

## Тон и стиль

- **Деловой**, без воды
- **Конкретные цифры** везде, где можно
- Не использовать "мы / нас / наш" — это нейтральный отчёт, не презентация
- Использовать **активный залог**: "Заработок составляет..." вместо "Заработок составляется..."
- В таблицах — **выделять цветом** ключевые цифры (зелёный заработок, красный убыток)
